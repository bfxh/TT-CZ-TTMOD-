03

符号系统

全站唯一符号表 · 43 枚 · 同一语义不得二次发明

这是本方案的核心交付。凡是能被一眼识别的语义，一律用符号承载，文字只做补充与兜底（tooltip / 无障碍 label / 首次引导）。符号统一 24×24 网格、1.7 描边、圆头圆角，与 iOS 同源。

禁用 emoji 当图标。 v3 用了 🔍 📊 📂 ☰ ▦ ◐ ⧉ ✕ —— 跨平台字形不一致、配色不可控、粗细不一，是"丑"的主要来源。
符号必须可被颜色接管。 全部 stroke="currentColor"，分类色直接由父级 color 注入。
内容区禁用纯符号。 指标条、卡片指标、列表列头、详情字段 —— 每一处都必须有中文标签。符号负责"快速定位"，文字负责"准确理解"，两者不可互相替代。
排序器与列头同词同序。 顶栏用「顶点数 / 三角面 / 体积 / 贴图数 / 文件大小」，卡片用「顶点 / 面数 / 体积 / 贴图」，列表列头与顶栏完全一致。

交互流程

「找到并判断一个资产」的最短路径
⌕ 输入

顶栏搜索，实时过滤名称 / 原名 / 路径

◈ 收窄

轨道点类型符号，浮层面板选具体类目

△ 排序

指标条点符号即按该指标降序，再点升序

⬡ 判断

卡片直接读到四项指标，无需打开

◉ 停靠

点击右侧停靠详情，列表仍可见可继续比

v3 需要 7 次交互 + 2 次全屏遮挡；v4 4 次交互、0 次遮挡。另补：⌘K 聚焦搜索、⌘1/2 切视图、⌘⇧D 切去重、←→ 在停靠状态下切换上下一个资产、Esc 关闭停靠。

缩略图策略

贴图 ≠ 模型 · 改为离线渲染每个模型自己的几何图

这是 v3 最严重的一处错误：缩略图直接拿「贴图文件」当预览，而贴图与模型是多对一关系，于是整屏出现大量一模一样的图。

旧：贴图当预览。 502 个模型共用同一张 button_0041.png；43% 的模型退化成图标占位，整屏一半图一半图标，视觉断裂。
新：离线渲染真实几何图。 build_thumbs.py 用 numpy 软件光栅化器逐个渲 OBJ —— 正交等轴测投影 + Lambert 明暗 + z-buffer，输出 256×256 透明底 WebP。
缩略图自带分类语义。 按 kind 上色（模块蓝 / 武器红 / 机甲橙 …），不用读到文字就知道它属于哪一类；透明底同时适配深浅色。
体积与速度。 约 5 KB/张（原 357 KB），渲染 11 ms/个，全量 31,611 个约 6 分钟，可中断续跑。
缺图优雅降级。 空模型 / 解析失败时回退为该分类的符号，而不是破图。
顺带解决：缩略图不再依赖贴图命中率，因此 13,694 个「无贴图」模型现在也有自己的预览；贴图回归它本来的位置 —— 停靠面板里的贴图列表。
